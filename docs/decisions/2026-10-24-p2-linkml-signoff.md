## Effect

**LinkML is adopted, limited to:**
- one LinkML schema for the authored vocabulary YAML;
- `gen-json-schema` as the only generator;
- `linkml validate` run in CI;
- the full 91-package set pinned, per the trial pin file.

**`gen-shacl` and `gen-owl` are no-go.** The vocabulary's SHACL stays hand-written, with
negative fixtures, in the repository's existing ladder. No OWL or RDF is generated by LinkML.
RDF comes from the repository's own deterministic serializer, which is ADR-003 D9 unchanged.

**What LinkML does not carry** (the trial's "cannot express" list): language-tagged labels,
derived status (D5), the D2 citation check, D3 history, the D4 spec §4 extraction, D6 claim
status and the quote tripwire, D8 declared agents, and content-minted IRIs. These stay in
`tools/vocab/` (P3) and the hand-written shapes (P4).

**ADR-003 can now be ratified.** This sign-off was the condition the architect set on
2026-10-23 (`docs/decisions/2026-10-23-adr-003-batch-digest-confirmed.md`, on branch
`ccv/p0-decisions`). ADR-003 D9 is annotated with this outcome on that branch.

## Not decided here

- **How the 91-package set enters the repository.** The options are a separate requirements
  file for the vocabulary toolchain, or a merge into `requirements-dev.txt`. Both normal CI
  jobs and the cold install time (over 10 minutes uncached in the trial) depend on that
  choice. P3 proposes it, and the architect's acceptance of the P3 PR decides it.
- **A Linux run.** The trial ran on Windows only, while CI is Linux. The first CI run of
  `linkml validate` and `gen-json-schema` in P3 is that measurement, and the
  `gen-json-schema` digest should be compared then.
