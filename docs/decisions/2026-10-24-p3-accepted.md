## Effect

1. **Dependency pin:** the 91-package LinkML set lives in `requirements-vocab.txt`, installed
   only by the separate "Vocabulary schema (LinkML)" CI job. `requirements-dev.txt` and the
   main job do not install it, and a test keeps the main suite from importing LinkML. This
   settles the question the P2 sign-off left open.
2. **`bco:` annotation properties:** the vocabulary's 19 `bco:` annotation properties and the
   `bco:PCFCode` datatype are declared in the generated `vocab/generated/bco-vocabulary.ttl`,
   not in `ontology/`. They are vocabulary metadata, not ontology classes. CLAUDE.md is
   amended to say so, so that "no BCO term exists" stays true of the ontology.
3. **Record digests:** a metamodel concept's record digest includes its specification §4 row,
   so a spec edit to a ratified definition breaks that ratification (ADR-003 D3).
4. **P5 scope:** **9** metamodel terms, not the 8 in the approved plan:
   - Business Capability;
   - Capability Map;
   - Capability Assessment;
   - Capability Maturity Rating;
   - Capability Sourcing Statement;
   - Capability Sourcing Assessment;
   - Capability Target;
   - Capability Target-State Specification;
   - Authorization Record.

   The 5 catalog terms are unchanged.
5. **PR #4 merges to `main` with a merge commit.**
